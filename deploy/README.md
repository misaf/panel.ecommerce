# Vendra ecosystem — Traefik reverse-proxy stack

This directory is the source of truth for the reverse-proxy stack. On a server
each subfolder is deployed to `/opt/apps/<name>/` (they are independent Compose
projects; paths in the examples below use the `/opt/apps` layout). The
architecture doc explains every decision:
<https://claude.ai/code/artifact/9b061b4a-a494-40b1-a491-7a6e72317fee>

One Traefik v3 instance is the only public entrypoint. Every app is an
independent Docker-Compose project discovered over the shared `traefik-public`
network. Nothing but Traefik binds `80/443`.

```
/opt/apps/
  proxy/              Traefik v3 (owns 80/443)
  vendra/             Laravel backend overlay (admin/console/reseller/api → :8080)
  vendra-website/   apex marketing site (Next.js :3000)
  property-template/  template used to scaffold storefront properties
  properties/<slug>/     one per customer, generated by stack.sh (gitignored)
```

No customer is committed to the repo. Storefront properties are scaffolded on
demand with `stack.sh property add` (see below).

## Host map

| Host | Serves | Container |
|---|---|---|
| `vendra.test` | Marketing site | vendra-website :3000 |
| `admin.vendra.test` | Admin panel | vendra :8080 |
| `<slug>.admin.vendra.test` | Tenant admin | vendra :8080 |
| `console.vendra.test` | Platform console | vendra :8080 |
| `reseller.vendra.test` | Reseller panel | vendra :8080 |
| `api.vendra.test` | **Canonical API (only API)** | vendra :8080 |
| `<customer-domain>` | Storefront (frontend only) | its own :3000 |

Storefronts call **only** `https://api.<BASE_DOMAIN>`. Customer domains serve no
API. See the architecture doc for the canonical-API + tenant-resolution design.

## First-time host setup

```bash
docker network create traefik-public

cd /opt/apps/proxy
cp .env.example .env                 # set BASE_DOMAIN; prod: CERT_RESOLVER=letsencrypt etc.
touch traefik/acme/acme.json && chmod 600 traefik/acme/acme.json   # prod only
# edit traefik/traefik.yml → ACME email; edit dynamic/middlewares.yml → dashboard hash
docker compose up -d
```

## Deploy vendra

```bash
cd /opt/apps/vendra
cp .env.example .env                 # BASE_DOMAIN + CERT_RESOLVER(_DNS) + DB creds
docker compose \
  -f /opt/apps/vendra-src/docker/docker-compose.yml \
  -f docker-compose.traefik.yml \
  --env-file .env up -d
```

## Add a new property

A **property** is a tenant store that belongs to a **reseller**. It has two
halves:

1. **Backend property/tenant** — created in Vendra (owns the admin at
   `<slug>.admin.<base>` and its data), provisioned by the app and attached to a
   reseller:
   ```bash
   php artisan vendra-subscription:provision "Abbas" abbas.com abbas_owner owner@abbas.com \
     --reseller=<reseller-id-or-slug> --plan=<plan>
   ```
2. **Storefront frontend** — the public Next.js site for that property, scaffolded
   by `stack.sh` (no folder is committed):
   ```bash
   bin/stack property add abbas abbas.com ghcr.io/your-org/abbas-storefront:latest
   bin/stack property up  abbas
   # Point the property domain's DNS A/AAAA record at this host.
   ```

`property add <slug> <domain> [image]` writes `properties/<slug>/` from
`property-template/` (its own independent Compose project) and, in local dev,
regenerates the self-signed cert to cover the new domain. Edit
`properties/<slug>/.env` any time (`STOREFRONT_IMAGE`, `STOREFRONT_PORT`, …). Other
property commands: `property up|down|restart|rm <slug>` and `property ls`.

## Running the full stack locally (no /opt copy)

You can run everything straight from this `deploy/` directory in the repo — the
compose files use relative paths. The realistic local outcome: **proxy + backend
up, with the admin, console, reseller panels and the API all reachable over
HTTPS.** Storefront and marketing containers stay down until you have Next.js
images to point them at (that is application work, not infrastructure).

### The quick way — `stack.sh`

`bin/stack` (a thin wrapper around `deploy/stack.sh`) drives the whole proxy +
backend lifecycle (creates the network, copies `.env` files on first run, starts
both projects, prints the URLs). Run it from the repo root; `./deploy/stack.sh`
works too.

| Command | What it does |
|---|---|
| `bin/stack up --build` | First run — builds the image, then network + proxy + backend |
| `bin/stack up` | Subsequent starts (no rebuild) |
| `bin/stack down` | Stop properties + backend + proxy |
| `bin/stack restart [--build]` | `down` then `up` |
| `bin/stack status` | Health-check the whole stack (docker, ports, cert, containers, endpoints) |
| `bin/stack logs [target]` | Follow logs — default vendra `php`; also `proxy`, a vendra service, or a property |
| `bin/stack open <target>` | Open a URL: `admin`\|`api`\|`console`\|`reseller`\|`dashboard`\|`<property>` |
| `bin/stack hosts [--write]` | Print (or append, with sudo) the `/etc/hosts` entries for every stack host |
| `bin/stack ps` | Docker status of proxy + vendra + properties |
| `bin/stack urls` | Reprint the local URLs |

Run `bin/stack help` (or no argument) for full usage. `bin/stack status` is the
quickest way to see what's wrong if a page won't load.

### One-time setup the script does *not* do

These are environment-specific, so you run them once by hand:

1. **Free ports `80/443`** — Traefik must own them; stop anything already bound
   (`sudo lsof -nP -iTCP:80 -sTCP:LISTEN` to check).
2. **Resolve `.test` → 127.0.0.1** — easiest via the helper (appends only what's
   missing, for base hosts + every property):
   ```bash
   bin/stack hosts --write     # or `bin/stack hosts` to print without writing
   ```
3. **Trusted certs (optional)** — without this Traefik serves a self-signed cert
   and the browser warns (still fine with `curl -k`). To trust it:
   ```bash
   brew install mkcert nss && mkcert -install
   mkcert -cert-file deploy/proxy/traefik/certs/local.pem \
          -key-file  deploy/proxy/traefik/certs/local-key.pem \
          "vendra.test" "*.vendra.test" "*.admin.vendra.test" \
          <your-property-domains…>
   ```
   Keep `CERT_RESOLVER` / `CERT_RESOLVER_DNS` **empty** in every local `.env`.
   (If you skip mkcert, `stack.sh` auto-generates a self-signed cert and extends
   it to cover each property domain as you add one.)
4. **Dashboard auth** — before opening `https://traefik.vendra.test`, set a real
   basic-auth hash in `proxy/traefik/dynamic/middlewares.yml`
   (`htpasswd -nbB admin '<pw>'`).

Then just `bin/stack up --build`.

### Verify

```bash
curl -k https://api.vendra.test/up         # → 200
curl -kI https://admin.vendra.test/         # → 302 /login
```

Then browse `https://admin.vendra.test`, `console.vendra.test`,
`reseller.vendra.test`, and the Traefik dashboard.

> Troubleshooting: the backend publishes MySQL on `127.0.0.1:3306` for
> convenience. If that port is taken, set `MYSQL_PORT=3307` in
> `deploy/vendra/.env` — the app reaches MySQL internally regardless.

### Storefront properties

Each customer storefront is scaffolded on demand (needs a built Next.js image):

```bash
bin/stack property add abbas abbas.test ghcr.io/your-org/abbas:latest
bin/stack hosts --write      # adds abbas.test (+ its admin subdomain) to /etc/hosts
bin/stack property up abbas
```

`property add` writes `properties/abbas/` (gitignored) and extends the local cert to
cover `abbas.test`. Manage with `property up|down|restart|rm <slug>` and `property ls`;
`stack.sh down` stops all properties too. The marketing site
(`vendra-website/`) is a fixed project you bring up the same way once you have
its image.

## Production certificates

Set in `proxy/.env` and each app `.env`:

```
CERT_RESOLVER=letsencrypt          # HTTP-01, per-domain
CERT_RESOLVER_DNS=letsencrypt-dns  # DNS-01, only for the *.admin wildcard
```

`letsencrypt-dns` needs a scoped DNS-provider token (`CF_DNS_API_TOKEN` in
`proxy/.env` for Cloudflare). Everything else validates over HTTP-01.
